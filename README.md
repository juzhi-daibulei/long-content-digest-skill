读完，不只是知道它讲了什么，而是知道它跟你有什么关系、哪里值得信、哪里值得偷师。

## 为什么做这个 skill

很多长内容的问题不是没人总结，而是总结完依然没法用。

行业报告会被压缩成一堆结论，访谈会被整理成金句，会议实录会被拆成纪要，爆款帖会被分析成套路。看起来信息都在，但用户真正想问的往往是：

- 这篇到底值不值得我花时间看？
- 它跟我现在做的事有什么关系？
- 哪些判断站得住脚，哪些只是说得漂亮？
- 如果我想学它的写法，最值得偷师的是哪一招？
- 能不能别给我一张表，像朋友读完之后跟我讲明白？

`long-content-digest` 解决的就是这个问题：把一篇长材料拆成自然、诚实、可继续行动的理解。

## 它解决什么问题

- 看行业报告、白皮书、峰会实录时，快速判断材料质量和跟自己的关系
- 看人物访谈、实战分享时，提取真正有启发的判断逻辑，而不是复述观点
- 看自媒体爆款帖、深度长文时，拆出结构、论证链条和可迁移写法
- 看课程、视频文字稿时，把高密度内容讲成好懂的核心思路
- 后续需要时，把拆解结果转成 PPT 大纲、思维导图或会议分享稿

这个 skill 不追求“看起来很专业”，而是追求用户读完第一屏就有反应：哦，我懂了。

## 它是怎么工作的

`long-content-digest` 不是单纯摘要，而是先判断材料和用户意图，再决定怎么拆。

1. **获取材料**：支持全文粘贴、文件路径、链接、截图文字、视频/课程转写稿。
2. **判断材料类型**：行业报告、人物访谈、会议纪要、论坛峰会、自媒体爆款帖、课程文字稿或其他长文。
3. **判断用户意图**：用户是想理清思路，还是想学写法；判断不出来才轻问一句。
4. **先给 30 秒速览**：一句话讲清材料是什么、质量如何、适合拿来做什么。
5. **自然展开**：按“思考辅助路”或“创作学习路”继续往下讲，不用表格堆标签。
6. **保留后续能力**：用户可以继续问原文有没有提到某点，也可以一键转成其他输出格式。

## 两条拆解路径

### 思考辅助路

当用户问“这跟我有什么关系”“帮我判断一下”“这篇对我现在做的事有没有用”时，skill 会像一个读完材料的朋友，讲清楚材料里哪些判断有用、哪些地方站不住脚、下一步可以怎么用。

它不会把所有东西机械拆成“风险/机会/行动建议”，而是围绕材料里的具体数据、案例和原话，自然说出真实判断。

### 创作学习路

当用户问“这篇为什么写得好”“爆款拆解”“我想学一下写法”时，skill 会拆它的开头、论证链条、结构和手法。

它会停在洞察层面：讲清这篇为什么成立、哪里值得偷师，但不直接生成标题、仿写模板或成品文案。那些是后续专门创作 skill 的工作。

## 效果示例

用户问：

> 这篇跟我现在做的会员体系有关系吗？

输出不会是表格，而会更像这样：

> 这篇挺值得看的，尤其是中间讲“高频低客单”和“低频高客单”分开运营那段，跟你现在想做的会员体系挺搭。
>
> 不过它这套是在电商场景验证过的，消费决策链条短、决策人就是使用者。你做的是 B 端 SaaS，用的人和付费的人经常不是同一个人，直接照搬可能会在“到底按谁的行为分层”这一步卡住。

更多语气和输出校准见 [`assets/output-examples.md`](assets/output-examples.md)。

## 适合拆什么

| 材料 | 适合怎么拆 |
| --- | --- |
| 行业报告 / 白皮书 | 判断材料质量、数据依据、适用边界 |
| 人物访谈 / 实战分享 | 提取判断方式和可迁移经验 |
| 会议纪要 / 演讲实录 | 过滤客套话，提炼真正影响行动的内容 |
| 论坛圆桌 / 峰会 | 处理多发言人观点，冲突时标明归属 |
| 自媒体爆款帖 / 深度长文 | 拆结构、论证链条和可偷师手法 |
| 课程 / 视频文字稿 | 把复杂内容转成可理解、可复述的思路 |

## 安装方式

### Codex

把整个 `long-content-digest/` 文件夹复制到你的 Codex skills 目录，例如：

```bash
mkdir -p ~/.codex/skills
cp -R long-content-digest ~/.codex/skills/
```

### Claude Code

```bash
mkdir -p ~/.claude/skills
cp -R long-content-digest ~/.claude/skills/
```

安装后，可以这样触发：

```text
帮我拆一下这篇长文
这篇跟我现在做的事有什么关系？
这篇为什么写得好？
把这个访谈拆成我能用的思路
```

## 边界

这个 skill 负责把长内容拆到“理解、判断、洞察、下一步”。

它不负责：

- 直接生成标题
- 直接仿写成品
- 主动调研一个行业
- 扮演材料作者本人
- 把普通摘要包装成复杂框架
